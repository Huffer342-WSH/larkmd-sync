# 原生画板同步

同步按每张图的来源处理。本地 Mermaid 和飞书 Mermaid 源码继续使用代码块；飞书原生画板保存原生节点和预览，不再自动改绘为 Mermaid。

## 1. 本地文件

```text
一本通.md
.assets/
  一本通/
    画板-1.board.svg
    画板-1.board.json
```

默认素材目录为 Markdown 同目录下的 `.assets/<文档名>/`，普通图片与画板源文件统一保存于此。旧的 `<文档名>.assets/` 等相对路径仍可读取和上传；拉取默认使用新目录，不自动删除旧素材。

Markdown 引用 SVG，常见 Markdown 浏览器可直接显示。`.board.json` 是画板源文件，保存节点、坐标、尺寸、样式、连线及各目标文档的同步基准；它不是可随意删除的缓存。图片名中的 `.board.` 用于识别原生画板资源，两份文件必须一起保留。

原生画板可在飞书或本地 SVG 编辑。不要修改 JSON 的 `bindings`、`baseline_hash`、`preview_hash`。上传成功并校验后，工具重新导出 SVG 并刷新原生数据；旧 JPG/PNG 预览的单独修改仍会被拒绝。

## 2. 同步行为

| 情况 | 行为 |
| --- | --- |
| 首次拉取原生画板 | 保存原生源文件、预览和同步基准 |
| 上传到新文档 | 创建空白画板，恢复原生节点，读回验证后建立映射 |
| 仅修改一处可唯一定位的普通文本 | 局部更新文本，保留原生画板块及 token |
| 章节增删等较大正文变化 | 插入新正文，移动保留的原生画板，再删除旧的其他正文块 |
| 原生画板未修改 | 保留原画板，不重建节点 |
| 只有本地源数据修改 | 更新同一个原生画板，验证后刷新预览及基准 |
| 只有飞书画板修改 | 保留飞书画板并刷新本地源数据及预览 |
| 本地和飞书均修改且内容不同 | 计划报告冲突，拒绝覆盖 |
| 拉取时本地源数据或预览有未同步修改 | 拒绝覆盖，先推送或解决冲突 |
| 目标画板已删除、同一画板重复引用、目标存在未映射原生画板 | 报告冲突，不猜测覆盖对象 |

该版本实现了原生画板保留和安全恢复，并非通用的文档块三方合并器。较大正文变化仍会重建其他正文块，评论、其他资源块和排版沿用现有同步限制。嵌在表格或列表容器里的原生画板暂时阻止回写。非 Mermaid 的特殊组件仍须单独判断是否支持。

## 3. 可靠性

原生接口的节点返回顺序不稳定，源文件按节点 ID 排序以保证同步计划稳定；比较内容时重映射服务端生成的节点 ID，并保留连接引用，忽略小于千分之一像素的浮点序列化差异。

每次恢复或更新后，必须读回校验节点内容。对飞书短暂返回“画板尚未就绪”进行有界重试，只有验证通过才更新本地同步基准。不同文档各自保存 token 与基准，不会根据源文档地址自动向其他文档写入。

多步云端更新不是事务。若中途失败，先核对实际进度并重新生成计划；源数据和同步基准不得伪装成已成功状态。预览和源文件应随 Markdown 一起纳入版本管理。

复杂原生图元和外部嵌入资源可能受飞书接口限制。读回不一致时拒绝更新同步基准。

## 4. SVG 编辑

原生画板拉取时导出SVG并保存为`.board.svg`，Markdown直接引用，`.board.json`继续保存节点、token和基准。编辑SVG后用push回传原画板；未改动的SVG不会触发节点重建。旧JPG/PNG引用在下次拉取时迁移，旧文件不自动删除。

SVG与JSON nodes不可同时编辑，修改SVG后拉取会报冲突，避免覆盖本地工作；远端同时修改也会报冲突。SVG必须自包含，不允许脚本、事件或外部引用。回传后检查原生节点与文字，再重新导出SVG更新基准。

SVG是视觉编辑格式，重新导入不保证原生分组、连接绑定等语义无损。旧节点保留在回传前的JSON，建议将资产纳入版本管理。SVG重建失败时不伪造成功基准。
