# Markdown 格式与往返约束

本页维护本地表示、编辑限制和格式转换边界。架构与开发入口见 [AGENTS.md](../AGENTS.md)。

## 同步方式

单篇文档以一个本地 `.md` 文件保存结构。普通图片直接保存；原生画板保存 SVG，并额外保存 `.board.json`，用于恢复原图和检测冲突。默认拉取结果在文件头写入文档映射：

```yaml
---
title: Design
feishu_url: https://tenant.feishu.cn/wiki/...
---
```

推送和比较时，工具移除这段 front matter，并把指向其他本地 Markdown 的链接转换为对应的飞书地址。单文档从目标文件的 front matter 取地址；文档树也可以只在命令中传入根 Wiki URL，再按本地目录层级和页面标题匹配子节点。正文中的 GFM 表格保持原样；表格在飞书中的宽度由飞书 Markdown 转换器决定。

单独成块的本地相对路径图片会上传为飞书图片。拉取时，飞书图片下载到 Markdown 同级的 `.assets/<文档名>/` 目录，并恢复为标准 `![说明](相对路径)`。本地图片当前支持 PNG、JPEG、GIF、WebP 和 BMP，且必须位于 Markdown 同目录或子目录。

图片上传通过唯一占位段落定位，再用文档块接口插入，兼容不支持 `--selection-with-ellipsis` 的 lark-cli。找不到唯一占位时会停止写入。

图片位于两个有序列表项之间时，工具会先上传 Markdown 和图片，再用飞书块更新恢复后续列表项的显式序号。外部输入仍是标准 Markdown，例如 `1.`、图片、`2.`；工具不会把 XML 或 block ID 写入本地文件。

fenced `mermaid` 会在推送时创建飞书画板。飞书 Markdown 接口能够导出源码的 Mermaid 画板会在拉取时恢复为 fenced `mermaid`。本地 Markdown 因此仍可直接浏览，不需要 `.mmd`、XML 或画板元数据文件。

以下 Mermaid 图表属于经过验证的双向同步能力：

| 图表类型 | 声明 |
| --- | --- |
| 流程图 | `flowchart` |
| 时序图 | `sequenceDiagram` |
| 类图 | `classDiagram` |
| 状态图 | `stateDiagram`、`stateDiagram-v2` |
| ER 图 | `erDiagram` |
| 甘特图 | `gantt` |
| 饼图 | `pie` |
| 思维导图 | `mindmap` |

其他 Mermaid 声明仍会透传给飞书，但不作为保证可往返的兼容范围。

飞书高亮块在本地使用 GitHub/VS Code 可直接显示的 Markdown Alert：

```markdown
> [!WARNING]
> 发布前检查配置，并保留 **粗体**、`行内代码` 和列表。
```

支持 `NOTE`、`TIP`、`IMPORTANT`、`WARNING` 和 `CAUTION`。推送时，工具按类型设置固定的飞书图标、背景色和边框色；拉取时根据图标恢复 Alert。Markdown 无法保存飞书任意自定义颜色，因此拉取计划会提示样式归一化。高亮块内暂不支持图片、代码块、表格、Mermaid 或其他资源块。

本地或远端写入都分成 plan 和 apply 两次调用。plan 读取当前文件哈希和远端 revision，但不保存计划文件；apply 重新计算同一个计划，任一侧发生变化都会拒绝执行。拉取文件使用同目录临时文件和原子替换，临时文件不会长期保留。

## SVG 画板

原生画板以 `.board.svg` 为唯一编辑源，配套 `.board.json` 仅保存映射与同步基准，不保留 nodes。首次上传可以只有 SVG；上传后读回最终 SVG 并刷新 JSON。旧 nodes 有未同步编辑时阻止迁移。首次创建按 SVG 比例设置显示区域，已有画板块的尺寸保持原值，详见 [原生画板同步](原生画板同步.md)。

### SVG 导出超时与缓存

SVG 导出遇到超时、服务器内部错误或限流时最多尝试 3 次，重试前分别等待 1、2 秒；权限、参数、输出格式等错误不重试。最终错误包含画板 token、尝试次数和总耗时，单次本地等待上限仍为 180 秒。持续超时会停止同步，不自动将原生画板降级为普通图片。

预检和执行仍重新读取远端正文及画板节点，保留计划与冲突校验。SVG 按页面、画板 token、调用身份、CLI 路径和完整节点内容缓存；节点未变时复用成功导出的 SVG，避免执行阶段再次请求导出。缓存保存在 `$XDG_CACHE_HOME/larkmd-sync/svg/`（默认 `~/.cache/larkmd-sync/svg/`），有效期 24 小时；过期或损坏时重新导出，可直接删除此目录清理缓存。缓存读写失败不会阻断已经成功的导出，推送后的 SVG 回读不使用缓存。

## 加粗边界修复

拉取时修复飞书导出的歧义加粗边界，例如 `**一句话读懂：**AC/VLT` 转为 `**一句话读懂：** AC/VLT`。仅在标点与相邻正文导致定界符无法识别时补空格，正常加粗不变；代码块、行内代码及转义定界符保持原样。

### Markdown 纠正模块

`core/markdown_correction.py` 提供 `correct_markdown()`，统一处理飞书 CLI 导出的 Markdown。同步流程为“CLI 获取正文 → Markdown 纠正 → 高亮块与资源转换 → 比较或保存”。纠正放在同步层，不混入 CLI 调用层；预检、实际拉取和远端比较复用同一处理，避免修正后产生虚假差异。

当前仅启用加粗边界空格纠正，范围限于加粗边界；不增加标题、列表、表格等纠正规则，不引入解析器依赖。同步模块不会修改原始响应对象，也不会因本地纠正自动推送远端。

## 标题编号双向保留

拉取时从飞书完整文档的 `seq-marker` 读取实际显示序号，不自行推算。本地标题包含可见序号和行末元数据，例如：

```markdown
# 1. 概述 <!-- larkmd-heading: {"seq":"auto","number":"1."} -->
```

注释不影响 Markdown 阅读。编辑时保留注释及工具添加的序号；可以修改标题正文或移动整行。推送先去掉工具添加的序号与注释，再通过飞书 CLI 将对应标题恢复为 `seq="auto"`。标题正文原本的数字保留；飞书按新位置计算编号，重新拉取后更新本地显示。没有元数据的手工编号不会自动转换为自动编号。

序号或元数据不一致时推送失败，不能通过猜测删除标题前缀；缺少远端序号或标题无法可靠匹配时保留原文并报告阻断警告。编号恢复属于独立的元数据转换模块，Markdown 格式纠正模块仍只修复加粗。
