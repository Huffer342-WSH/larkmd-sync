# 架构与代码地图

## 三个入口，共用一套业务

Python 调用者从包根导入 API；CLI 解析参数后调用相同 API；Agent 从内置 Skill 选择 CLI 命令。Python 包与 Skill 分别显式安装。

```text
Agent → 内置 Skill → cli.py → api.py ← Python 调用者
                                ↓
                             sync.py
                         ↙            ↘
                resources / core    board_sync
                         ↘            ↙
                           lark_cli.py → 官方 lark-cli
```

## 模块职责

所有路径相对项目根目录，公开导出以 [__init__.py](../src/larkmd_sync/__init__.py) 为准。

| 职责 | 实现入口 | 验证入口 |
| --- | --- | --- |
| 公共 API、预期错误返回与诊断回调 | [api.py](../src/larkmd_sync/api.py)、[result.py](../src/larkmd_sync/result.py) | [test_api.py](../tests/test_api.py) |
| 参数、JSON envelope、退出码 | [cli.py](../src/larkmd_sync/cli.py) | [test_cli.py](../tests/test_cli.py) |
| 快照、plan/apply、正文比较、树映射 | [sync.py](../src/larkmd_sync/sync.py)、[models.py](../src/larkmd_sync/models.py) | [test_sync.py](../tests/test_sync.py) |
| 图片、Mermaid、引用与资源转换 | [resources.py](../src/larkmd_sync/resources.py) | [test_resources.py](../tests/test_resources.py)、[test_download_fidelity.py](../tests/test_download_fidelity.py) |
| 原生画板保留、更新和读回 | [board_sync.py](../src/larkmd_sync/board_sync.py)、[board_assets.py](../src/larkmd_sync/core/board_assets.py) | [test_board_assets.py](../tests/test_board_assets.py)、test_sync.py |
| 标题元数据、加粗、颜色、列表与高亮块 | [core/](../src/larkmd_sync/core/) | tests 中对应主题测试 |
| 实时进度和等待提示 | [progress.py](../src/larkmd_sync/progress.py)；由 API 绑定 diagnostic，CLI 输出 stderr | [test_progress.py](../tests/test_progress.py) |
| 官方 CLI 子进程、超时和 SVG 缓存 | [lark_cli.py](../src/larkmd_sync/lark_cli.py)、[config.py](../src/larkmd_sync/config.py) | [test_lark_cli.py](../tests/test_lark_cli.py) |
| Skill 生命周期、归属、哈希与原子替换 | [skillkit.py](../src/larkmd_sync/skillkit.py) | [test_skills.py](../tests/test_skills.py) |
| Skill 命令接入与目标选择 | [skill_cli.py](../src/larkmd_sync/skill_cli.py) | test_cli.py、test_skills.py |

`core` 保存格式与数据规则，不启动飞书 CLI；外部 I/O 集中在适配层，业务编排位于同步层。暂不为每个格式建立服务类或子包。Skill 安装器沿用现有实现，不为统一模板覆盖本项目的兼容修复。

## 修改如何落到代码

新增格式先确定本地表示和保真边界，再修改对应 core 转换及资源/同步调用点，最后验证 plan、apply 和 diff 使用相同表示。修改画板必须同时检查基准、token 和读回失败路径。修改 CLI 时先确认公共 API 能表达该操作，再适配参数和输出。

详见 [同步设计](同步设计.md)、[格式约束](Markdown格式.md) 和 [开发约定](../AGENTS.md)。

## 公共接口与发行边界

默认拉取逐篇读取、校验并保存；默认推送检查计划后执行。dry_run=True 只返回计划；plan_id 用于重新校验并执行指定计划；预期错误返回 ApiResult，诊断通过 diagnostic 回调接收。CLI 统一输出 schema 1，具体字段和退出码见 [CLI 参考](../src/larkmd_sync/skills/larkmd-sync/references/CLI.md)。

Skill 唯一内容源随 wheel 与 sdist 发布，通过包资源读取，不依赖仓库位置。安装 Python 包与安装 Skill 是独立步骤；远程渠道只分发 Skill，不自动安装 CLI。

skillkit 共享安装归属、内容哈希和原子替换逻辑。相同内容重复安装无修改，升级使用 update；未知来源或本地修改默认拒绝覆盖，卸载不接管未知目录。修改前用 --dry-run 预览实际目标，--dest 指向 Skill 的父目录。

skill doctor 报告 CLI 位置和内置 Skill 有效性；已安装状态由 skill status 查询，版本兼容由内置 check_cli.py 预检。这些职责目前分开提供。

包版本统一维护在 pyproject.toml、包 __version__、uv.lock 和 Skill metadata.skill-version；cli-min-version 表示兼容下限。JSON schema 和安装清单版本独立维护，不随包版本机械递增。

标签发布由 [release.yml](../.github/workflows/release.yml) 编排：版本检查 → 离线测试 → 构建与包资源检查 → 独立安装 → GitHub Release。提交说明由 [release_notes.py](../scripts/release_notes.py) 从版本标签之间的 Git 历史生成；对应行为由 [test_release_notes.py](../tests/test_release_notes.py) 验证。发布操作方法见 [README](../README.md)。
